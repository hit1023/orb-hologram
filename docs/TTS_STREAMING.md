# 声を文ごとに分けて、先頭から再生する（引き継ぎ）

2026-11-01 に入れた変更の引き継ぎメモです。Aivis ルーター（`hit-aivis-router`）側の `/speak_stream` と、orb-hologram 側の実装の両方を説明します。

## なぜやったか

h-2 / h-3 / h-1 の Aivis は CPU だけで合成します（各 4 コア）。エンジンは合成中に 4 コアを使い切るので、並列にしても速くなりません。
78 文字の文章で、1 台あたり約 5〜7 秒（h-1 は約 10 秒）かかります。目標は「遅くても 4 秒」でした。

総処理時間は変えられないので、**文ごとに分けて、先頭の文ができしだい再生を始める**ことにしました。体感の待ち時間は最初の 1 文ぶん（2 秒前後）になります。
同じモデルを複数ノードに載せずに済むので、ルーターの「1 モデル 1 ノード」の方針は崩れません。

## orb-hologram 側（実装済み）

`index.html` の `speak()` を次のように変えました。

1. `splitSentences(text)` で文に分ける。`。！？` と改行で区切り、8 文字未満の断片は次の文にくっつける。60 文字を超える文は読点（、）で区切り直す。
2. 文ごとに `POST /api/tts` を呼ぶ。**1 文ずつ順番に依頼**する（前の文の合成が終わってから次を依頼。同じ台で CPU を取り合わないため）。
3. 先頭の文が届いたらすぐ再生を始める。前の文の再生が終わったら次の文を再生する（再生中に次の文の合成が進む）。
4. 口の動き（音量連動）は、全部の文で同じ `AnalyserNode` を共有する。

### 挙動の決まり

| 状況 | 動き |
|---|---|
| 1 文目の合成が失敗 | これまでどおり、ブラウザの `speechSynthesis` で全文を代用 |
| 2 文目以降の合成が失敗 | そこで読み上げを終える（代用の声は出さない。二重にしゃべらないため） |
| 割り込み（全二重・`stopSpeaking()`） | `turn` カウンタで古い合成結果を捨て、代用の声も出さない |
| 16 文字以下の文 | これまでどおり `orb-api` がメモリに覚える（`ttsCache`）。文ごとなので当たりやすくなった |

`orb-api/server.js` は変えていません（`/api/tts` は 1 回 1 文のまま。`X-Session-Id` で同じ台を使い続ける仕組みもそのまま効きます）。

### 触るときの注意

- 文の区切り規則は、ルーターの `app/splitter.py` と同じ考え方で JS に書き直したものです。**直すときは両方そろえてください。**
- `replyCap.dur`（吹き出しの表示時間の目安）は、文が始まるたびに足しています。最初の文の時点では全体の長さは分かりません。
- 感情（`emotion`）は全部の文に同じものを付けます。

> 2026-11-01 追記: Aivis Cloud はルーターを通さず `orb-api` から直接呼ぶ構成にした（`AIVIS_CLOUD_API_KEY`）。ルーターを通るのは CPU 版（h-2）だけ。

## ルーター側（実装済み）: `POST /speak_stream`

`/speak` と同じ本文に `max_len`（1 文の最大文字数、既定 60）を足した形で受け取り、**できた文から順に NDJSON** で返します。

```
{"i":0,"n":3,"text":"今日はいい天気ですね。","backend":"http://192.168.0.21:10101","audio":"<MP3 の base64>"}
{"i":1,"n":3,"text":"...","backend":"...","audio":"..."}
{"error":"音声合成に失敗しました"}        ← 失敗したときは、この行で終わる
```

- 合成は同じセッション・同じ台で順番に行います。テキスト置換・プリセット・発話履歴は `/speak` と共通です。
- Aivis WebUI（`hit-aivis-webui`）はこちらを使っています。MP3 は連結してもそのまま再生できるので、ダウンロードは全文ぶんを連結したものです。
- orb-hologram が使っていないのは、予備への切り替え（Cloud ⇄ CPU）と感情ごとの調子（`VOICE`）が `orb-api` にあるためです。ここをルーター側に寄せる場合は、`/api/tts_stream` を `orb-api` に足して、この API を中継してください。

## 動作確認のしかた

```bash
# ルーター: 文ごとに返ってくること（最初の行が出るまでの時間を見る）
curl -sN -X POST https://aivis-api-cpu.s-quad.com/speak_stream \
  -H 'Content-Type: application/json' \
  -d '{"text":"今日はいい天気ですね。散歩に行きましょう。お昼は何にしようかな。","speaker_id":258599616}' \
  | while read -r l; do date +%T; echo "$l" | cut -c1-80; done
```

orb-hologram は `https://holo.s-quad.com/` で、長めの返事が返る質問をして、しゃべり始めるまでの時間が短くなったことを確認します（`orb-api` のログに `[tts] ... ms` が文ごとに出ます）。

## 今後の候補

- 先頭の文が 30 文字を超えると最初の読点で 1 回だけ切る（実装済み）。さらに短くする場合は `first_max` を下げる。
- 速い台（h-2 / h-3）にだけモデルを置き、遅い h-1 を外す（ルーターの無効化ボタンで可能）。
- 複数台での並列合成は、同じモデルを複数ノードに載せるので見送り中。
